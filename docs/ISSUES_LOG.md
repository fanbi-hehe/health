## 二、用户反馈问题详情

### P1 动作库突然为空

- **反馈**：用户打开动作库发现 170+ 动作全没了。
- **根因**：数据库版本升级走了开发期"清库重建"，但 DataStore 里"已初始化"标记还在，内置动作/食物不会重新导入。
- **处理**：`FoodRepository` / `ExerciseRepository` 初始化逻辑改为"标记已初始化 **且表非空** 才跳过"，表被清空时自动重新导入。
- **教训**：开发期清库策略与初始化标记组合会静默丢数据，现已用真实 Migration 彻底替代清库策略。

### P2 动作库返回跳到计划页

- **反馈**：动作详情页返回后，训练页跳回"计划"Tab，还丢失滚动位置和展开状态。
- **根因**：训练页 Tab/搜索/展开状态用普通 `remember`，离开导航栈后状态重置。
- **处理**：改为 `rememberSaveable`，Tab、搜索词、展开分组、列表滚动位置全部保留。

### P3 AI 对话记录训练不生效

- **反馈**：跟 AI 说"记录深蹲 4组 10次 60kg"，训练记录里没有。
- **根因**：最初用正则解析，覆盖句式有限（不认"记录"开头、无组次、动作库外动作名）。
- **处理**：升级为 **function calling**（`record_training` 工具），模型理解自然语言并输出结构化参数，本地白名单校验后写库；正则降级为兜底。

### P4 AI 添加食物写不进食物库

- **反馈**："添加食物，蛋白粉，每百克 1768 千焦"弹窗成功但食物库没有。
- **根因**：解析器只认 kcal/千卡，不认"千焦"，且 AI 只是文字回复没有执行动作。
- **处理**：① 千焦自动换算 kcal；② 升级 function calling（`add_food` 工具）；③ 支持完整营养描述（每百克热量 + 蛋白/碳水/脂肪）。

### P5 AI 添加食物不记饮食记录

- **反馈**：添加蛋白粉后饮食记录里看不到（用户期望"60克"是一次饮食摄入）。
- **根因**：`add_food` 只写食物库，没写饮食记录。
- **处理**：工具增加 `amount_g` 参数，用户说了本次分量时，自动按比例生成今日饮食记录（热量 + 宏量），餐别按时间自动判断。

### P6 拍照识别从 v0.4 开始不可用

- **反馈**：0.1 可用，0.4 起拍照识别失败，用户逐版回退定位。
- **根因**：v0.4 代码审查修复时，把图片解码改成"先采样再解码 + EXIF 旋转"，特定设备/照片在这两步解码失败。
- **处理**：`ImageCompressor` 完全回退到 v0.1 逻辑（直接解码 → 缩放 → 压缩），仅保留解码失败提示防御。
- **教训**：**该文件禁止再改回采样/EXIF 方案**，见 DEVELOPMENT.md 排查章节。

### P7 相册/多图识别无法读取照片

- **反馈**：新增相册多图识别后，无法读取照片；删多图保留单张仍失败。
- **根因**：问题不在相册选择器（v0.15 仅拍照仍失败），实为 P6 图片解码问题叠加。
- **处理**：P6 修复后相册入口已删除；如需恢复建议改用老式文件选择器，并先真机验证。

### P8 宏量不随重量快捷调整联动

- **反馈**：确认页点 ±50g，热量变了但蛋白/碳水/脂肪不变。
- **处理**：快捷按钮改为按重量比例同时重算热量与三大宏量。

### P9 看板切换卡顿

- **反馈**：切到看板"卡卡的"。
- **处理**：① 看板 ViewModel 提升 Activity 级常驻预热；② 关闭图表动画；③ 图表改为 Compose Canvas 自绘，移除 Vico 重型库。已大幅改善，真机确认中。

### P10 近 7 天柱状图难看

- **反馈**：柱状图丑。
- **处理**：自绘重做：圆角柱、达标绿/未达标橙、粉色虚线目标线、日期标签。

### P11 步数涨得慢、不实时

- **反馈**：步数"涨的不对，明显慢了"。
- **根因**：步数只在进入看板那一刻同步一次，停留页面不刷新。
- **处理**：看板可见期间每 30 秒自动同步；离开自动停止。
- **已知限制**：轻量档不常驻后台；手机重启后传感器归零会丢当天部分基数。

### P12 多食物识别变差

- **反馈**：一张照片多个食物时，现在的版本识别不全。
- **根因**：v0.9 在识别 Prompt 里强制要求每项返回宏量，免费视觉模型顾此失彼。
- **处理**：先弱化宏量要求（v0.19），最终把识别 Prompt **完全回退 v0.1**（v0.24），宏量改由语言模型在每日复盘时统一估算。

### P13 识别后等宏量估算又慢又没结果

- **反馈**：识别流程变慢，宏量还没结果。
- **处理**：删除识别后的同步估算，宏量估算移到"AI 每日复盘"（对宏量为 0 的记录批量估算，只进总结不写库，失败不影响）。

### P14 数据库升级清空数据

- **反馈**：每装新版本数据被清。
- **根因**：开发期 `fallbackToDestructiveMigration(true)`。
- **处理**：考古 v1→v8 全部表结构，编写 7 段真实 Migration 并注册，移除清库策略；用 SQLite 脚本实测校验通过。
- **红线**：后续改表必须同步新增 Migration（见 DEVELOPMENT.md 4.2），**禁止恢复清库**。

### P15 热量消耗估计不完整

- **现状**：BMR、GPS 运动消耗、步数消耗、手动补录、净摄入/缺口均已上线。
- **未完成**：米环 7 心率广播接入（Keytel 心率消耗公式已就绪，缺 BLE 数据源），需求文档见 HEAT_ASSESSMENT_REQUIREMENTS.md。

### P16 照片方向不自动纠正

- **现状**：为恢复识别稳定性回退到 v0.1 解码（不做 EXIF 旋转），拍照照片在部分设备可能横竖颠倒。
- **建议**：如需修复，用"解码成功后再单独旋转"的温和方案，并先在真机验证。

### P17 训练记录无日期回看与月历

- **反馈**：要求训练记录页像饮食页一样支持翻看往日，并加月历跳转。
- **处理**：v0.26 实现共用 `CalendarPickerDialog` 组件，饮食页与训练记录页均支持日期切换 + 月历跳转。

## 五、维护建议（防止问题复发）

- `ImageCompressor` 保持 v0.1 解码方案，改动前先看 P6 记录；
- 数据库只走 Migration，禁止清库（P14）；
- AI 工具只加"写/改"白名单，禁止删除工具；
- 大段自然语言解析优先 function calling，正则只做兜底（P3/P4 教训）；
- 图表/重 UI 优先自绘，避免重型库拖慢页面（P9/P10）；
- 每个修复版本都要打 APK 并标注版本号，方便用户回退定位（P6 全靠逐版回退才找到根因）。
